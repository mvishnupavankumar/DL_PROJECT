# AegisOps — Production Readiness Gap Analysis

**Audit Phase**: Phase 10  
**Auditor**: Senior Python Engineer / ML Researcher / SRE / Security Reviewer  
**Scope**: 16-Dimensional Production Readiness Assessment (Site Reliability & AppSec)

---

## 1. Dimensional Assessment Matrix

| Dimension | Evidence-Based Current Status | Gap Severity | Recommended Remediation | Prerequisites / Dependencies | Required Verification Test |
| :--- | :--- | :---: | :--- | :--- | :--- |
| **1. Monitoring Reliability** | In-browser fragment polling (`@st.fragment`) by default; headless worker daemon exists but has no supervisor or health-check. | **High** | Wrap `collectors.worker` in a system service (Windows Service / systemd) with automated restart policy and liveness heartbeat. | OS service supervisor (`NSSM` / `systemd`) | Kill collector process; verify supervisor restarts it within 10s without missed intervals. |
| **2. Data Quality & Persistence** | Single SQLite database (`data/aegisops_live.sqlite3`). No schema migration tool (Alembic). Concurrent writes from UI and worker risk database locks. | **Medium** | Switch to PostgreSQL for multi-process concurrency, or enable SQLite WAL mode with connection pooling. Add Alembic migrations. | SQLite WAL mode or external DB | Run 10 parallel collectors writing to SQLite; verify zero `sqlite3.OperationalError: database is locked`. |
| **3. Detection Quality** | 5-feature LSTM model + static threshold OR-gate. No concept of seasonality, noise filtering, or gradual drift adaptation. | **High** | Implement adaptive baselining (e.g. EWMA / Prophet) alongside autoencoder. Remove static rule masking from evaluation metrics. | Baseline telemetry store | Simulate gradual memory creep; measure time-to-detection vs static rules. |
| **4. Diagnosis Reliability** | In offline mode, uses hardcoded keyword matches. In LLM mode, prompt is vulnerable to hallucinating nonexistent causes. Uncaught API exceptions crash pipeline. | **Critical** | Add strict Pydantic output validation against verifiable evidence citations. Add retry loop with exponential backoff on Groq client calls. | `pydantic`, `tenacity` | Inject mock Groq 429 rate-limit error; verify graceful retry and fallback to offline mode. |
| **5. Remediation Safety** | Hardcoded to only execute `clear_demo_service_fault`. Does not support arbitrary actions. | **Low** (Safe by restriction) | Maintain fixed runbook actions; implement pre-condition and post-condition invariants before executing any production command. | Safe executor sandbox | Attempt executing an unlisted action; verify immediate rejection. |
| **6. Authentication & RBAC** | Completely unauthenticated. Anyone accessing port 8501 can request, approve, and execute actions. `approver_label` is freeform text. | **Critical** | Integrate OIDC / OAuth2 authentication provider (Okta/Keycloak). Enforce RBAC where requester and approver must be distinct identities. | Auth provider, HTTPS proxy | Attempt approval from an unauthenticated session; verify HTTP 401 Unauthorized. |
| **7. Secret Management** | `.env` loaded via `python-dotenv`. Placeholders filtered in `config.py`. No secrets committed. | **Low** | Store tokens in environment secrets store (AWS Secrets Manager, HashiCorp Vault, or DPAPI on Windows) rather than plaintext files. | Secret manager client | Verify secrets do not appear in process environment dumps or logs. |
| **8. Network Exposure** | Both Streamlit (8501) and FastAPI demo service (8765) bind to `127.0.0.1` by default. | **Low** (Safe if local) | Bind to loopback strictly. Add TLS certificate termination via reverse proxy (Nginx/Caddy) if exposed over LAN. | TLS certificates | Port scan host machine; verify ports 8501 and 8765 refuse external non-loopback connections. |
| **9. Audit Integrity & Retention** | Events stored in SQLite `incident_events` table. No write-only append lock or external forwarding. Records can be altered via SQLite client. | **Medium** | Stream audit events to an immutable append-only log store (e.g. AWS CloudWatch, Datadog, or external SIEM). | Syslog / SIEM integration | Verify audit log records match actual network actions during incident replay. |
| **10. Fault Tolerance** | If demo service is unreachable, collector records status 0; if Streamlit crashes, collection halts unless worker runs. | **Medium** | Decouple telemetry ingestion from visualization. Decouple agent orchestration into asynchronous worker queues (Celery/Temporal). | Message broker (Redis/RabbitMQ) | Simulate web UI crash during active incident; verify collector continues persisting metrics uninterrupted. |
| **11. Deployment & Restarts** | Manual scripts (`run_all.ps1`, `run.bat`). No containerization (Docker/Compose) or Kubernetes manifests. | **Medium** | Create multi-stage `Dockerfile` and `docker-compose.yml` for test service, worker, and dashboard. | Docker Desktop | Execute `docker compose up`; verify complete environment starts up cleanly. |
| **12. Backups & Recovery** | No automated SQLite backup or point-in-time recovery. | **Low** | Add daily SQLite `VACUUM INTO` backup script or backup volume mount. | Backup storage target | Corrupt active database file; verify restoration from backup restores historical telemetry. |
| **13. Performance & Resource Usage** | Lightweight. In-memory footprint < 150 MB. CPU usage < 2% during idle polling. | **Low** | Telemetry table lacks partition pruning; `SELECT * FROM telemetry_samples` will slow down after millions of rows. Add table retention policy. | SQL cleanup job | Insert 1,000,000 mock rows; verify recent query latency remains < 10ms with timestamp index. |
| **14. Observability of AegisOps** | AegisOps monitors other targets, but has no Prometheus `/metrics` endpoint or health check for itself. | **Medium** | Expose `/metrics` on collector worker and dashboard (reporting sample drop rate, agent latency, queue depth). | `prometheus_client` | Scrape AegisOps with Prometheus; verify collector liveness is alertable. |
| **15. Configuration Management** | Mixed configuration in `config.py`, environment variables, and Streamlit session state. | **Low** | Consolidate configuration into a unified Pydantic `BaseSettings` object with validation. | `pydantic-settings` | Start app with invalid port or URL; verify clear configuration error before startup. |
| **16. Testability & Reproducibility** | Passing 34 unit tests. Excellent deterministic seeding. Missing live Groq tests and UI integration tests. | **Medium** | Add integration test suite using `pytest-mock` to test Groq client responses, timeouts, and rate limits. | `pytest-mock`, `respx` | Run full test suite in CI pipeline; verify 100% pass without requiring real external API keys. |
